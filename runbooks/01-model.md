# 01. Агент і памʼять

[Усі етапи](README.md) · [Попередній](00-setup.md) · [Наступний](02-telegram.md)

**Перед початком:** гілка `start`. **Результат етапу:** `step-01-model`. Змінюємо лише `src/`.

## Що робимо й навіщо

Учора, щоб отримати першу відповідь моделі, ми писали запит, потім масив повідомлень, потім цикл. Сьогодні пишемо лише те, що відрізняє нашого агента від будь-якого іншого: яку модель брати і що їй сказати. Решту бере Flue.

Перевіряємо агента в терміналі, без Telegram. Так простіше дивитися, що відбувається.

## Чого бракує зараз і що зміниться

У `src/` поки немає агента. Після етапу:

- `src/agent.ts` описує агента: модель та інструкцію. Жодного циклу, масиву `messages` чи `generateText`.
- `npm run ask` надсилає агенту одне повідомлення і друкує відповідь.
- Агент памʼятає розмову між запусками. Учора `messages[]` зникав разом із процесом, сьогодні історію зберігає Flue за id розмови.

## Маленькі зміни

### 1. Позначка модуля агента

Створи `src/agent.ts` і почни з трьох рядків:

```ts
'use agent';

import { useModel } from '@flue/runtime';
import { DEFAULT_MODEL } from './models.ts';
```

`'use agent'` стоїть першим рядком файла, до імпортів, як `'use strict'`. Вона каже Flue: у цьому файлі живуть агенти. Так `flue run` і сервер Flue знаходять агента без окремої реєстрації.

`DEFAULT_MODEL` приходить з `src/models.ts`, це модель першого дня `groq/qwen/qwen3.8-27b`. Файл уже лежить у `start`.

### 2. Агент як функція

Нижче додай саму функцію:

```ts
// Flue викликає цю функцію перед кожним запитом до моделі. Цикл і історія розмови на ньому.
export function Assistant() {
  useModel(process.env.MODEL || DEFAULT_MODEL, { thinkingLevel: 'off' });

  // Рядок, який повертаємо, стає інструкцією агента (system prompt).
  return [
    'You are a personal notes assistant in Telegram. Reply in Ukrainian, briefly.',
    'Say so when you do not know something.',
  ].join('\n');
}
```

Учора агент був обʼєктом `news` з полями `model`, `system` і `tools`. У Flue агент це функція. Вона повертає інструкцію, а можливості додає викликами `use...`, їх називають хуками. `useModel` обирає модель з рядка `провайдер/модель` у `.env`, а якщо `MODEL` порожній, бере `DEFAULT_MODEL`. `thinkingLevel: 'off'` вимикає міркування Qwen: на безкоштовному Groq кожен токен на рахунку, а для нотаток міркування не потрібні.

Flue викликає цю функцію заново перед **кожним** запитом до моделі. Це схоже на компонент React, який перемальовується при кожній зміні. Поки це нічого не дає, але на етапі 04 саме так ми будемо вмикати тул лише для власника.

Інструкція англійською, як і вчора: так її стабільніше читають моделі. Відповідати просимо українською.

### 3. Стабільне імʼя

Останній рядок файла:

```ts
Assistant.agentName = 'workshop-assistant';
```

Під цим імʼям Flue зберігає розмови агента. Якщо колись перейменуєш функцію, історія не загубиться.

Перевір типи:

```bash
npm run check
```

### 4. Перше повідомлення

```bash
npm run ask -- "Привіт! Що ти вмієш?"
```

Скрипт `ask` запускає `flue run src/agent.ts --id terminal --message "..."`. Відповідь моделі друкується в кінці. Вище Flue сам показує кроки: повідомлення користувача, відповідь асистента, id розмови. Учора ці рядки ми друкували власним `console.log` у циклі.

### 5. Памʼять між запусками

Надішли два повідомлення поспіль:

```bash
npm run ask -- "Мене звати Оля, запамʼятай."
npm run ask -- "Як мене звати?"
```

Друга відповідь знає імʼя, хоча це два окремі процеси. Обидва запуски мають `--id terminal`, тому Flue продовжує ту саму розмову. Історію він тримає в `node_modules/.cache/flue/run.db`.

Тепер той самий запит з іншим id:

```bash
npx flue run src/agent.ts --id someone-else --message "Як мене звати?"
```

Імені агент не знає: інший id означає іншу розмову з порожньою історією. На наступному етапі id розмови стане id чату в Telegram, і в кожного користувача буде своя памʼять без жодного додаткового коду.

## Перевірка

```bash
npm run check
npm test -- --test-name-pattern "^(00|01) "
```

**Автоматична перевірка:** 3 тести без мережі. Тест `01 Памʼять` підставляє скриптовану модель і дивиться, що в другому запиті до моделі вже є перше повідомлення, а в розмові з іншим id його немає.

**Очікуємо вручну:** відповідь українською на `npm run ask`, а на «Як мене звати?» агент називає імʼя з попереднього запуску.

**Якщо не так:**

- `Provider is not configured`: у `.env` порожній ключ саме того провайдера, який стоїть у `MODEL`.
- `Unknown model`: звір `MODEL` з таблицею в [підготовці](00-setup.md#3-ключ-моделі).
- Агент не памʼятає імʼя: перевір, що обидва запуски йшли через `npm run ask`. `flue run` без `--id` щоразу починає нову розмову.

```bash
git add src
git diff --cached --quiet || git commit -m "Моя спроба етапу 01"
git fetch origin
git switch -c work-02 origin/step-01-model
npm run check
```

Твій коміт лишився в попередній гілці. `.env` і `node_modules` лишаються на місці. Якщо `work-02` вже існує, візьми інше імʼя, наприклад `work-02-retry`.

Якщо встиг сам, продовжуй у своїй гілці з [етапу 02](02-telegram.md).
