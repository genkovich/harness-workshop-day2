# Ранбуки · день 2

Йдемо зліва направо: пояснення → невеликі зміни src → перевірка → висновок. Усі інструкції та тести є в кожній гілці. Готова гілка — контрольна точка після етапу, а не наступна вправа.

| Етап | Навіщо | Готова гілка |
|---|---|---|
| [00 · Підготовка](00-setup.md) | Підготуємо середовище окремо від практики. | `start` |
| [01 · Перша відповідь через Flue](01-model.md) | Учора ми писали цикл самі. | `step-01-model` |
| [02 · Повідомлення з Telegram](02-telegram.md) | Повідомлення має дійти до агента й повернутися саме у свій чат. | `step-02-telegram` |
| [03 · Тули для нотаток](03-tools.md) | Модель не може записати нотатку самим текстом відповіді. | `step-03-tools` |
| [04 · Settings і перевірка дозволів](04-permissions.md) | Інструкція «не видаляй чуже» не гарантує заборони. | `step-04-permissions` |
| [05 · Журнал і корисний feedback](05-feedback.md) | Хочемо бачити, що сталося насправді. | `step-05-feedback` |
| [06 · Skill для стендапу](06-skill.md) | Стендап потребує порядку роботи й формату відповіді. | `step-06-skill` |

На ранніх гілках запускай тести за командою свого етапу. `npm run check` запускає весь набір і призначений для step-06-skill та main. Пізні тести на start закономірно ще не проходять.

Ми використовуємо runtime Flue, а не переписуємо цикл першого дня. SQLite належить сесії runtime; notes.json — навчальні дані застосунку. Розподілене виконання, повноцінна авторизація й памʼять із гібридним пошуком сюди не входять.
